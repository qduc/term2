# Term2 built-in tool inventory audit — 2026-10-19

Completed a mechanical census plus a bounded, assisted usefulness audit. **No current tool has enough evidence for removal.** Preserve current behavior while testing the strongest concrete overlap: `memory_retrieve` versus `memory_search` followed by `memory_get`. This is a comparison candidate, not an approved consolidation. “Retain” below means preserve the current conditional surface pending stronger evidence; it does not mean proven indispensable.

## What the data supports

The census covers 945 conversation JSONL files, 1,928,980,413 bytes, spanning 2026-08-09 through the frozen 2026-10-19T01:18:53Z cutoff. It identifies 59,934 unique direct starts, 59,918 paired starts, 16 unmatched starts and 6,135 duplicate persisted results, which are not additional calls. A separate deduplicated census finds 34,893 named nested call records inside `run_code`. Direct starts, wrapper calls and nested records are different layers; they must not be summed as distinct tasks or successful effects. Named nested records can include validation and unknown-tool failures.

The semantic audit covers 159 selected direct-call envelopes across all 46 historical literal names, plus ten supplementary nested wrappers containing all four named `propose_goal` records and all six `get_subagent_result` records. The direct sample includes every direct call for names with at most four starts and up to four mechanically diverse sessions for each larger population. It is purposeful coverage, not a random outcome sample. All 16 unmatched-start gap snapshots are retained separately. Other nested uses were counted but not comprehensively reviewed.

Current source has a possible union of 41 built-in registration names, 40 of which appear under the same literal historical name. This excludes dynamic MCP tools and conditional script-only agent bridge capabilities. Historical-only names are `bash`, `memory_synthesize`, `task`, `tools`, `tools.create_file` and `tools.read_file`. Their absence from the current literal union is not six newly justified removals, nor proof of alias equivalence. [Current registry](/home/qduc/term2/source/agent.ts:488).

This is enough to identify local contributions, distinct recovery capabilities, friction and replacement hypotheses. It is insufficient for exposure-adjusted utility, population failure rates, whole-task success rates or a safe retirement decision. Inspected logs do not establish effective per-request offered catalogs or historical app/runtime versions. Zero use cannot distinguish disabled exposure, absence, discoverability or lack of a suitable task. Selected envelopes omit neighboring tool calls/results and most downstream work; an unanswered whole-task question in one local step is not tool failure. Negative lookups, source orientation, controlled writes and stop requests can each contribute useful local evidence.

## Decisions that matter

1. **Test memory retrieval composition first.** Current `memory_search` and `memory_retrieve` share ranked search machinery; the former returns summaries/snippets, while the latter loads full records with omitted/unavailable-record budgeting. Compare real lookup tasks using the same memory snapshot and total budget. Require preserved answer evidence, scope handling, unavailable/omitted records and paging; measure round trips, output size, latency and cost. If search plus get is worse on these dimensions, the convenience tool has demonstrated value. Historical empty or unrelated retrievals alone do not justify removing it. [Implementation](/home/qduc/term2/source/tools/memory/memory-tools.ts:271); cases A084–A091.
2. **Treat `run_agent_workflow` as an exposure/ownership question.** It has zero observed direct and named nested use, but its setting defaults off and registration is conditional. First establish whether the specialized workflow surface is still intended and has suitable enabled tasks. Any comparison with `run_subagent`/`run_code` must cover result quality, approvals, cancellation, parent-state isolation and orchestration behavior; equivalence is unproven. [Registration](/home/qduc/term2/source/agent.ts:677), [default](/home/qduc/term2/source/services/settings/settings-schema.ts:647).
3. **Preserve rare control and recovery capabilities.** `get_subagent_result` is explicitly a re-fetch path because completion notifications normally inline the final result; `get_subagent_status` never returns final report/diff evidence. Supplement N003 returns a mentor review and N008 a verifier report with a failed assertion claim and runtime limits. Other records show active refusal, missing lookup and failed-run reporting; those states are distinct. `memory_delete` has one direct observation but supplies actual deletion rather than correction, a distinct data-control capability. Cancellation and monitor-stop tools control different lifecycle objects. Low counts cannot measure their avoided loss or replacement burden. [Result/status contracts](/home/qduc/term2/source/tools/agent/run-subagent-async.ts:268), [deletion](/home/qduc/term2/source/tools/memory/memory-tools.ts:444).
4. **Investigate goal/catalog consistency before judging the goal tools.** A102 is an unknown-tool attempt, A063/A066 reject checks without an active goal, and N004 rejects array criteria. N005/N007/N009 then report approved persisted goals through wrappers. These are evidence of distinct availability/state/schema conditions and useful registration signals; they do not independently prove host dispatch, approval receipts or goal achievement. Historical runtime uncertainty prevents labeling them current defects. [Proposal](/home/qduc/term2/source/tools/agent/propose-goal.ts:14), [self-check](/home/qduc/term2/source/tools/agent/goal-check.ts:18).
5. **Measure the actual surface cost before optimizing the name count.** With `run_code`, current assembly binds the wrapped registry to scripts and filters the directly offered tools; nonessential script entries use compact signatures, with full descriptions available on demand. Without `run_code`, the existing direct surface remains. Search and editing alternatives already depend on settings. Forty-one registered names do not mean forty-one simultaneous full schemas, and removing one does not establish a meaningful prompt-cost saving. [Direct surface](/home/qduc/term2/source/lib/agent-factory.ts:391), [script catalog](/home/qduc/term2/source/tools/system/run-code/tools-header.ts:145), [conditional editors](/home/qduc/term2/source/agent.ts:591).

The minimum useful next evidence is an effective offered-catalog/schema hash with runtime version and profile/settings context, invocation-stage outcomes, and paired replacement-task results. Link opportunity to a task need rather than merely counting turns where a tool name was present. Measure actual token/latency/maintenance cost before a removal claim. These are proposed follow-ups; this audit changes no product behavior.

## Screening quality and limits

Mechanical selection preserved complete selected text, pointers and hashes. Fresh native Luna agents screened all selected segments; tool-free Haiku independently reviewed complete source packets against those cards. All selected user-request text is attached losslessly to the primary payload. Primary review used the refined cards and current contracts, checked targeted source evidence and retained independent review. No source commands were executed and no model was authorized to remove tools.

Calibration finally preserved 98/98 frozen material propositions across 40 cases after repairs and primary interventions. The final four fresh cases preserved 11/11 propositions through generic Luna plus Haiku review and mechanical repair. This supports bounded assisted use, not autonomous evidence deletion or a corpus-wide recall estimate. On eight matched fresh cases, direct first-pass Luna preserved 17/25 propositions (8 partial); direct first-pass Haiku preserved 15/25 (7 partial, 3 absent). Both failed the strict first-pass criterion. The comparison includes different delivery harnesses; Haiku is useful as an additional source reviewer, not a demonstrated superior replacement for Luna.

All 159 main cards now pass quote, source integrity, segment accounting and invocation-binding checks (2,622 checked quotes); the supplement passes 57 exact-quote checks with all ten requests intact. These checks do not prove semantic completeness. Remaining interpretation defects required primary corrections, including failed lookup versus failed run, reported baseline versus observed result, and progress across omitted intervening work versus contradiction. Corrections, earlier versions and independent inspections are retained. Thus the filter is ready for assisted judgment and remains unsuitable for unattended discard/removal decisions.

The initial 22-case calibrated payload was about 23% smaller than its canonical selected source fields. No uniform compression ratio is assumed for this audit. The main value is deduplication, explicit sampling and a capsule index with retrievable evidence, not proven safe semantic exclusion. The full primary packet retains citations and user requests; provenance overhead and reviewer expansion can offset compression. In this run the main selected source text was 931,560 characters and the full canonical judge JSON was 1,685,769 characters, including citations and lossless requests; the 169-case capsule text was 68,217 characters. These different representations are not a token-cost comparison. The full cited packet is not an overall compression win; capsules serve as navigation with evidence available on demand.

Recorded Haiku CLI cost for the audit plus repairs/supplement was **$1.667893**, across 182 retained responses, excluding earlier calibration; this is the CLI-reported estimate, not billing reconciliation. The observed alias resolved to `claude-haiku-5-5`. Luna cost is unavailable, so total cost and a Luna/Haiku price comparison cannot be established.
