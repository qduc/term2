# Direct TUI integration

This subtree targets the direct contract at `0a27e1345abff53e45c781f59e95a176db309d16` and its M2/Session prerequisites. The app must provide a direct host connection, theme/skin providers, exit/session switching and the app-owned `TuiIntegration.command` local/host/config actions. It must not implement a generic slash wire RPC or call Session/Engine from the client. Missing optional domain operations must remain unavailable; no bridge fallback.

The connection hook applies C4's `reduceWireEvent` to the retained public wire snapshot and projects that state for display. Fresh connections start with their snapshot. A `DirectReplayConnection` requires a retained snapshot for the same session whose durable `seq` equals `replay.fromSeq`; it is not reset before applying catch-up events. The optional `onSnapshot` callback makes the current public state available to the app for reconnection; the app is responsible for keeping the state/cursor from the same consumption cut and not treating transient events as durable replay history. Closing this TUI detaches the connection and does not cancel the session.

Ctrl+G opens request-specific approval and question UI. Structured questions use the wire's IDs, labels/descriptions, custom and multi-select flags; all answers are sent in one `answers` decision. Decline and stop are distinct. Only allow/deny are offered for approvals: scoped grants are not invented. With no structured question schema the fallback is a single text answer. Session remains responsible for validation, durable acceptance and release.

When an active foreground turn is reported, Enter submits `delivery: steer` and Alt+Enter submits `follow_up`; when idle Enter uses `auto`. `/steer <text>` and `/followup <text>` explicitly select delivery. These require the real `submitWithDelivery` capability; unavailable is displayed and the draft is retained. Alternate terminal encodings of Alt+Enter and interaction/editor handoffs require terminal verification. Clipboard image data from ink-prompt is raw base64; it is sent as image content with MIME type. Queue edits omit attachments, retaining existing images; the exported queue helper can explicitly replace/clear them. Queue controls send typed operations and surface unavailable.

History is separate from the live CLI at `envPaths('term2').data/tui-history-next.json`; text only, atomic file replacement and errors surfaced. Concurrent direct TUI processes can still race. Transcript row scrolling renders skin/markdown offscreen; long activity panels, ANSI/style handling, Unicode/wrapping and streaming performance require real terminal checks. App-owned session/history/config navigation and complete old CLI parity remain.

The current contract still exposes `timeline: null` when mixed order is unavailable and nullable reasoning step/identity; the client cannot reconstruct the true mixed message/tool order or split reasoning by model step without Session/C4 support. Subagent wrapper events and transient retry/compaction notices are not retained by the shared public reducer; the app currently projects public state only, so those transient display details require a wire/read-model extension or explicit local event presentation. Tool content images are represented as text placeholders. Store metadata and M3/M4 feature capabilities remain owner dependencies.

No testing, behavioral probes, typechecks, guards, builds, independent review or cold reads have run. Post-M6 checks must establish direct snapshot/replay equivalence and cursor boundaries, questions/decisions, input handoff/Alt+Enter encodings, attachments/queue delivery, terminal rendering and failure paths before claiming M5 parity.
