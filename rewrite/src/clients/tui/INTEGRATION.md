# Direct TUI integration

This subtree targets the staged direct protocol at `82d37ded91705090bc6b253301c7411ac5d5e389` and native command writer `f14c9baa`. The app owns connection, theme/skin providers, exit, host commands and session switching. Missing capabilities surface their real errors; the TUI does not call Session/Engine or create a fallback runtime.

The client folds `reduceWireEvent` into a fresh snapshot or a retained snapshot at the exact replay cursor. The app must retain state and cursor from the same consumption cut. Closing detaches without cancelling. Mixed transcript order is used only when supplied by `timeline`; unmatched tool results and other unordered items are identified separately. Images in tool results are placeholders.

`useClient` also requests the existing atomic background-notification drain when its initial snapshot or a reduced wire event shows undelivered notices and an idle foreground/queue. This is an admission request, not a second notice consumer: Session selects the pending batch, records delivery, and owns the silent turn. Busy admissions wait for the next wire event; no timer or user submission is needed, and paused queues are not resumed. The request does not touch the composer. Detaching stops further requests from that connection without cancelling an already admitted turn. The direct headless driver remains separate.

A pending interaction belonging to the active root turn takes keyboard ownership automatically when no explicit task, budget or rewind overlay is open. `InteractionView.turnId` and `taskId` retain wire ownership rather than inferring it from display labels; task-owned requests do not take over the foreground composer. The ordinary composer keeps its draft but is inactive while the keyed interaction panel owns input. The session keeps one stable modal key listener: panels and structured questions publish their handlers during layout commit, rather than installing fresh passive Ink subscriptions after their first visible frame. The ordinary editor also rejects keys at delivery time while inactive. A rendered panel alone does not establish that a newly mounted `useInput` subscription has taken ownership. The ordinary Enter send/steer footer uses the same activation condition as the editor, so overlays, a disconnected connection or a pending submission do not advertise keys the ordinary composer cannot consume. Ctrl+G returns from any interaction panel to the preserved composer without resolving or cancelling the request, so `/answer` and steering remain accessible. Only that exact root request is dismissed from automatic presentation; a new request takes ownership again. From the composer Ctrl+G opens the request-ID-scoped picker, including background requests and only explicitly advertised grants; Ctrl+B handles pending budget requests with explicit human extend or stop. The approval panel exposes `y`/1 for Allow once and `n`/2 for optional rejection-reason entry (empty Enter denies without a reason), with a separate explicit no-reason choice. A denial shortcut may arrive in the same terminal input chunk as its reason: the panel consumes the leading `n` and preserves the exact remaining text in the reason editor. Approval still requires the exact single `y` key; pasted or coalesced `y…` does not grant approval. Modified keys are not approval shortcuts. `Questions` owns structured question presentation; the pending-interaction summary does not echo all raw question arguments and expose non-current pages as active content. While pending, the `ask_user` tool header stays a neutral tool-name summary rather than repeating every page prompt. Completed tool output and its question/answer display remain visible; they are not an active question page. The question editor keeps partial answers local, supports `n`/`p` navigation, and places multi-select Continue directly after the offered options; it sends the complete typed answer set once rather than dispatching on navigation. Escape from an automatically selected approval cancels the foreground; from the first question it declines the question. Explicit picker/back navigation remains local. Decisions carry user provenance. `/tasks` displays supplied task data and sends selected task-ID-scoped operations; host task control can be unavailable, and acknowledgements do not imply completion. `/cancel` reports the actual targeted abort result and discarded IDs when available.

The approval panel has no input-timing guard: nothing is dropped for arriving too soon after the panel opens. Input is still ignored while a decision is already in flight; approval shortcuts are ignored during reason/text entry or with Ctrl/Alt held; a lone `y`/`Y` allows, and Enter acts on the selected option (Allow by default, but Deny or a grant if the selection moved). A 20 ms opening handoff window existed (note 95) but was removed by supervisor note 109 (confirmed in note 111; the owner speaks only through the supervisor's notes), because it dropped a deliberate Enter written the instant the frame appeared (`source/task-menu-row-wrap.e2e.test.ts` failed ~20-25% of runs with it, 0/22 without; evidence n110/n113). A narrower burst rule (typeahead only if the previous key came <50 ms earlier in a run that began before the panel rendered) was tried and cannot work: the original race probe's arrival key follows the previous key by 130-135 ms and the task-menu Enter by 90-208 ms, and with the rule both probe arrival keys approved the tool (evidence n116). Accepted by that note, reversible trade-off (rare, needs unusual timing): keys typed ahead in the composer that land on the panel after it opens (the probe's `arrival-enter`/`arrival-y`) will approve; a typed-ahead lone `y`, or an Enter while Allow is selected, can allow a tool call. The held-send confirmation (`send-confirmation.tsx`) keeps its own 20 ms handoff window; it has no test that depends on an instant key.

When no interaction is pending, composer Ctrl+G (including raw BEL) opens the same task manager as `/tasks`; a pending interaction retains priority. The manager keeps live, foreground-first task rows visible while showing selected details, budgets each label against the terminal width including row decorations, and tracks selection by task ID. Arrow keys select tasks even with details open. `b` then Enter requests the selected foreground task's move to background. “Moved to background” requires a supplied background mode, not merely an accepted command. Completed tasks leave the live list. The native port had lost this retained keyboard/list workflow; changing the original terminal test to `/tasks` would conceal that omission rather than fix it.

Enter steers during an active turn, Alt+Enter submits a follow-up, and idle Enter uses auto delivery. Queue operations use native commands; the queue editor retains original non-primary content, sends replacements only when changed, and never automatically resubmits a late edit. If content is unavailable it cannot recover unknown attachments. `/rewind` restores the Session draft and only resends on explicit request. Plain text, `/steer`, `/followup`, `/skills <name> <request>` and rewind-resend call the `preview` wire command first; when it requires confirmation (input surge, or large uncached input such as after a rewind) the draft stays in the composer behind a `y` / `n`|Esc prompt and nothing is dispatched. The wire `submit` does not enforce this guard itself, so any new TUI send path must preview. Not previewed: queue edits (queue-active skips the large-input check) and no re-preview at `y`. History uses `envPaths('term2').data/tui-history-next.json` and stores image bytes; question answers are excluded. Concurrent history writers can race.

The direct app supplies `TuiIntegration.preferences(sessionId)` from the attached session's live settings, not launch defaults or another session. The composer passes `ui.pasteThreshold` to the shared `MultilineInput`: collapsing a large paste changes its presentation, not submitted content. Existing `/settings` changes take effect on the next render. Generic clients without that callback use schema defaults through the host-owned `terminalPreferenceDefaults` access boundary.

`ui.historySize` bounds composer recall, not canonical conversation/transcript data. `readHistory` validates the entire file before returning the newest whole entries; `appendHistory` atomically retains the newest configured count including text and attachments. The editor applies the same bound to session fallback history and in-memory navigation. The schema keeps this preference startup-only; `/settings` does not make it live-modifiable. A changed supplied bound resets navigation position without changing the current buffer/cursor; the next successful history append persists the new bound. Older recall entries are then irreversibly removed from this separate file. Malformed files remain untouched and errors stay visible; there is no automatic recovery, retry, new default, or settings migration.

`onLiveEvent` receives newly folded, durable events after the current snapshot/replay cut, never snapshots or duplicate sequence numbers. The direct app uses it for new approval interactions and successfully completed turns through the existing `useTerminalFocusNotifier`; cancelled/failed/interrupted turns are not response-ready notifications. Initial history, session attachment, idle renders and snapshot refreshes are silent. The notifier owns focus tracking and all three notification preference gates. Focus reports are excluded from composer text, without taking keyboard ownership from decisions, menus or signal keys.

The missing preference consumers were latent at the native adapter boundary: retained settings existed, but component defaults, unbounded recall and an absent notifier bypassed them. Settings readback could not catch that category. Keep preferences sourced from the attached session and observe actual paste submission, recall persistence and raw child-PTY notification output when changing this integration. Sibling source consumers (`InputBox`, `HistoryService`, `useTerminalFocusNotifier`) already consume these preferences; native transcript retention and background notices are separate owners, not replacement preference consumers.

Idle rendering must quiesce: wire projections retain identity until the immutable snapshot changes, and the controlled image editor must ignore equal echoes and the initial empty callback on remount. A new ink-prompt version must preserve that remount callback ordering or the draft-restore adapter must change. Verify both a real idle terminal's CPU and image draft restoration; a visible prompt alone cannot detect a render loop.

The opt-in `TERM2_HARNESS_IDLE_PATH` observer must follow the native composer's committed value and activation condition, not infer readiness from visible prompt text. `useHarnessInput` publishes the shared harness acknowledgement after commit; a foreground turn or an inactive composer cannot publish idle. The native port originally omitted this observer, so real terminal tests saw generation zero even with a rendered idle editor. Keep the existing built-CLI tool-row workflow as the regression boundary: it requires startup readiness, typed-value acknowledgement and a fresh idle generation after each turn. Passing that workflow does not establish legacy log-schema or task-menu compatibility.

The app's `switchSession` attaches the successor and returns an optional notice after publication (including a control socket rebind failure). The unkeyed exported `Tui` retains that notice above its keyed session child. `/bridge` uses app-owned socket lifecycle callbacks.

App-owned `/auto-approve`, `/effort` and `/profile` without arguments return an argument-entry draft (`/<command> `) through `TuiIntegration.command`; they must not configure the session or turn missing arguments into usage errors. `/model` without an argument opens a keyboard-owned Favorites/All picker with filtering and persistent Ctrl+F favorites; Escape cancels and Enter selects through the existing model command. The trigger is cleared, and the composer is inactive while the picker owns keys. `/auto-approve` without an argument also names the current mode, `/model` and `/effort` confirm a completed change with the new value (any other receipt keeps the command-id notice), and the shared `/settings` summary lists `shell.autoApproveMode` and `sandbox.enabled`; `/auto-approve <mode>` normally saves to the shared settings file (the save can fail, and the reply says so), so a session on the owner's HOME can also change the old CLI. The no-argument reply reads this session's in-memory value, which after an uncertain rebuild may be ahead of what tools use; the configure receipt notice flags that case. The existing composer remains the input owner, and submitting the completed draft uses the same explicit-argument path. `/resume` opens a keyboard-owned workspace-local conversation picker with the selected summary as a preview; Escape cancels and Enter switches sessions. `/resume ls` prints one line per conversation, newest first: ID, local time of the last fact and the first user message (`(no messages yet)` before a turn; the session store supplies `title`/`updatedAt`); other arguments remain exact native session IDs. The port originally retained only execution paths and lost these source-command entry semantics. Check both the intermediate draft and the eventual consumer effect: successful explicit commands alone cannot detect that regression. Accepted commands clear the composer; a rejected command stays in it so it can be edited.

Retry, compact, rewind and rollover use a fresh stable UUID per deliberate invocation and are sent once. Pending is not success; transport loss or interrupted outcome is reported as uncertain, without automatically repeating the effect. The retained ID can be queried with `/command-status <id>`; `/command-apply <id>` explicitly restores a completed rewind draft or follows a completed rollover successor. A pending rewind originally requested as resend is restored for review, not automatically resent. Snapshot command receipts remain visible except settled configure successes and rejections, which are shown once by the invoking command instead. Settled compact receipts are folded: a latest definite failure remains as one human-readable line until a later compact succeeds; a successful compact leaves no persistent receipt row. Pending and interrupted compact receipts keep their IDs and status recovery. Pending and interrupted configure receipts remain visible for recovery. App-owned configure commands need the same keyed receipt semantics; they are not implemented by this subtree.

A supplied terminal notice is rendered alongside accepted Session notices, including goal-stop and completion-verification blockers. The TUI does not infer it from interrupted status or tool text; the wire terminal owns its exact message, and the next foreground admission clears that terminal presentation.

This interface note is not a verification certificate. Integration verification must cover snapshot/replay, input ownership and terminal rendering (including automatic foreground versus explicit background decisions), attachments and late queue edits, task and budget decisions, switching/rebind notices, and actual application integration. Module presence or an accepted wire receipt alone is not proof that the keyboard workflow reaches the next provider/tool output.

## Internal ownership

`index.tsx` retains the unkeyed terminal interrupt gesture and cross-session notices;
`session.tsx` owns the keyed session, ordered commands, modal routing and the shared
composer/editor-footer activation condition. Moving the session component does not
move the stable modal listener or install another keyboard owner.

`session-composer.ts` owns the editor draft, image echo/remount reconciliation,
attachment restoration, queued-edit draft snapshot, and interaction/queue ID lists
captured when typing a numbered command. It installs no input listener.
`interaction-command.ts` validates a numbered `/answer` against that captured list
and returns the exact request/decision; the session sends it with user provenance.

The shared `TuiProps` contract carries the app's live-event callback through the
unkeyed shell and keyed session into `useClient`. History-size reaches `useEditor`
through `useSessionComposer`; paste threshold and focus-sequence filtering stay at
the session input surface alongside the inactive-composer guard. Terminal preference
checks do not establish unrelated modal, task, budget or switching workflows.

Native TUI helpers must stay within the native dependency boundary. The task menu
previously imported the source CLI's terminal-width helper: runtime checks passed,
but the existing layer guard rejected the integrated candidate, as with the idle
hook. Task-row width/truncation now lives privately with its native consumer,
retaining the same conservative ASCII/non-ASCII cell accounting. Run
`node rewrite/scripts/check-layers.mjs` on the exact branch before calling it ready
and immediately before each pick; typechecks and runtime checks do not establish
this boundary. Do not add an adopted directory or widen the allowlist for helpers.

A tool's wire `display` from source tools is the legacy command-message list (or `{messages, approvalPresentation}`). `ToolCall` shows each message's `command` (only when the concise header does not already contain it, e.g. a truncated long shell command; not for `search_replace`, `create_file` or `run_code`, whose input is listed below instead) and its `output`, each only when `detail` or the text content does not already hold it. For `search_replace`, `create_file`, `run_code` and long `run_subagent`/`run_subagent_async` `task` strings (not an `agent_spec` goal) it also lists what the model asked for from the tool input (`-`/`+` edit lines, new file content, the script, the full task; capped at 40 lines), since the concise header only summarises it. `apply_patch` still shows no diff. Unrecognised `display` shapes still render as JSON rather than being dropped. Dumping `display` as JSON printed the whole message array under every shell block.

A `history_replaced` notice (compaction, rewind, retry) is shown as its own sentence without the internal kind label (`direct-reducer.ts` `historyReplacedMessage`, `direct-projection.ts`). It does not report before/after sizes: the event carries only the reason. `/copy` confirms with `Copied to clipboard.`; the tour's report of no visible confirmation was not reproduced against a fixture provider (the e2e asserts the confirmation).

The composer shows matching direct slash commands while typing a command name. Up/down select; Enter completes a menu pick into the draft, and Tab opens a selected no-argument model or resume picker when available, otherwise completing into the draft. Escape dismisses and clears the slash trigger; a fully typed command name, with or without arguments, runs on plain Enter; the composer consumes those keys only while the menu is visible. The direct port retained command execution but omitted discovery, so the terminal journey checks the intermediate menu and completion as well as command execution.

The bar under the composer (`composer-footer.tsx`, the skin's `StatusBar`) shows profile, provider/model, effort and approval mode (`YOLO` in the danger colour for `always`), then session token totals and cache share. `TuiIntegration.status(sessionId)` supplies the settings-derived parts on each render. It shows no speed, context window, cost or quota: the direct snapshot carries only session usage totals (not the last request's), and no provider quota, so nothing is invented. The per-turn `model · status · usage` line is gone from the transcript region; only a non-idle status and cost remain there. The live Tasks block lists running or waiting tasks only, without ids; settled tasks stay in the task manager.

The idle composer hints include `@ paths` and `! shell`. A leading `!` runs an explicit user command locally in the workspace without a model turn, using the existing shell executor and output limits; the result is shown as a notice. This direct execution is not a model tool call and is not added to the conversation log or model context. It is rejected with the input retained while a turn runs, for attachments, or for SSH workspaces (where it must never fall back to local execution). The old direct CLI lacked this entry path; use a real-PTY regression to distinguish direct execution from asking the model to run a shell tool.

Tool calls are one row each (`✓ <what it did> (63ms)`; shell titles use the single-line call description, or `Shell command` when absent, with the command available when open; the runtime comes from a shell result's `Runtime:` line, other tools show none). Output, nested-run details and scripts stay behind Ctrl+O (an on-demand scrollable transcript viewer that shows every tool's output, settled tools included); failed calls collapse to a ✗ summary; shell failures include a short exit/timeout and an explicitly labelled fatal/error line when available, with full details under Ctrl+O (including non-zero exits or timeouts reported by `success:false` despite `isError` false). Outcome-unknown calls, running calls (live progress) and `ask_user` (its answer) stay open, and successful `search_replace`/`create_file` edit lines stay visible as diffs. Expanded detail is laid out beneath the header across the available width.

Reasoning is live turn activity: the wire snapshot retains its last reasoning after `turn_ended`, but the TUI must not render it without an active foreground turn. The terminal regression holds a reasoning stream open to check both its live display and its removal after completion.

A cancelled turn's partial reply has no final message, so the snapshot keeps it flagged as a draft. Only the active turn's draft renders as live streaming text at the end of the transcript; a stale draft of an ended turn renders as a normal message at its timeline position. Before this, every later reply (also after `--resume`) appeared above the stale draft, which the tail-following viewport then showed instead, so replies looked lost (reproduced with real Codex: a cancelled 400-word essay, quit, resume, two prompts). Ctrl+C stops a running turn first and keeps the draft (the old terminal cleared the draft first; this order is deliberate); with nothing running it clears the draft (a pending background interaction alone does not make Ctrl+C cancel while a draft is typed), and a second Ctrl+C within two seconds exits.

The composer filter (`composer-filter.ts`) submits a chunk that is one line of text plus a single trailing `\r`: while a turn streams, an automated sender's text and Enter can reach the terminal as one chunk, which the editor would take as a newline and leave unsent (reproduced by side with `herdr pane send-text`; the old terminal's composer behaves the same, since it uses the same editor, so this is not a regression). A bracketed paste keeps its `\r` as a newline (the filter tracks the paste markers on the raw stream, because Ink strips them before the key handler runs), and a chunk with several lines (an unbracketed paste) keeps the editor's behaviour. The submitted text is the current draft plus the chunk's text (it assumes the cursor is at the end of the draft), and the draft is cleared with the send (the chunk is never inserted, so nothing else would clear what was typed before it). Automated senders should still pause about 300 ms between text and Enter and check that the draft cleared.

Inline code renders as a chip on the theme's code background (`MarkdownRenderer.tsx`, shared with the old terminal): the chip carries one padding column on a side only where an ordinary space stood, and that space is dropped, so lines read with single spaces and nothing lands between a chip and following punctuation. Bold and italic wrappers are transparent to neighboring spaces. At the start of a list item the bullet already supplies the separator, so no extra leading chip column is added. Table cells keep unpadded code.

The slash menu and `/help` read one table (`slash-commands.ts`): the menu lists each command with its description (truncated to the line), and `/help` puts keyboard shortcuts first, followed by every command with the same description. A command added to the app must be added to that table (the menu would not offer it otherwise); a table entry the app does not implement fails visibly when run.

The normal transcript commits settled, ordered history to Ink Static and keeps active or uncertain history in a live tail. The terminal owns scrolling and selection for committed rows; Ctrl+O opens a bounded full-session expanded viewer, and `/help` has its own bounded viewer. Unknown-order or unresolved rows are not committed. Successful clear, session switch and rewind clear the screen and terminal scrollback before redrawing, matching the old CLI; resize clears only the visible screen after the old debounce. Previously committed rows cannot reflow until a redraw. Ink Static must receive the terminal width explicitly: without it, its separate layout emits oversized rows that the terminal breaks mid-word. The `/help` viewer is paged to the available viewport; PgUp/PgDn or arrow keys scroll and Escape closes it. Two chips with one space between them share that space: only the first carries the padding.

A message sent while another send is still in flight is not dropped. Earlier the composer was inactive during a send (`busy`), so keys, including a whole `text\r`, vanished before the editor saw them; the composer now stays active during a send (the harness idle flag still waits for it). If Enter arrives while a send is in flight, the message goes back into the composer with the notice `Still sending the previous message. Press Enter again to send this one.` rather than being sent concurrently or deferred (a deferred send would run against stale state, and could reach a session the user had left or collide with a held-send confirmation). So a sender that submits two messages back to back may need to press Enter again for the second one; it is never lost. Other limits: two messages in one chunk (`a\rb\r`) stay a multi-line draft by note 135; text typed during a held send's preview, or an image pasted while a send is in flight, can be replaced or cleared when that send finishes; the engine's own merging of two quick steers is unchanged.

`@` path completion (`path-menu.tsx`, `workspace-paths.ts`, behind `composer-menu.tsx` together with the slash menu): typing `@` at the start or after whitespace opens a list of workspace paths (relative to the process working directory, breadth-first, root `.gitignore` honoured, `.git` and `node_modules` skipped, 5000-entry cap with a notice). Rank: basename prefix, basename substring, then path substring (no looser matching, so a draft ending in an ordinary `@word` finds nothing and Enter sends it). The menu works on the end of the draft (the cursor position is not available in render state), the workspace is rescanned each time the menu opens so files created mid-session appear, symlinks are not listed, and paths with spaces are inserted unquoted. Up/down select, Enter inserts the path and a space, Tab inserts it without one, Esc dismisses (Enter then sends the text as typed). A directory inserts as `@dir/` (keeping the `@`) so the menu stays open to continue inside it. It is native: it does not use the legacy `usePathCompletion` hook, `PathSelectionMenu` or `file-service`, which pull the old input context into the layer check; the cost is that its ignore rules are only the root `.gitignore`, not nested ones. It lists the launch directory, so a session opened for another workspace root still completes from the launch directory.

The TUI's targeted foreground cancel atomically removes pending steers and returns their current text and images to the composer. The existing draft comes first, then steers in queue order separated by blank lines; the notice says the queued message is back in the input. The composer supports text and images but not arbitrary text/image interleaving: it carries image bytes and explicitly warns if their position relative to text changes. This is unsent draft state and is not restored on reconnect. A steer submitted against a turn that stopped before admission is rejected and returned to the draft instead of opening another turn. Ordinary queued follow-ups keep their existing pause behavior. Other clients retain their targeted-abort defaults; old cancellation facts retain their recorded replay behavior.

## Render cost

Anything called from a render must be cheap. `app.sessionDetails()` reads and parses the whole conversation log, so it is not allowed on the render path (it burned about one core in long sessions); render code uses `app.liveSettings(sessionId)`, which reads the log once per session. The live tail and on-demand transcript viewer render at most about eight times a second and skip the state update when the frame is unchanged. Static rows do not get repeated in later live frames; PTY tests must not assume the last header starts a frame containing the whole transcript. Measured with a pty probe on a streamed reply: 73.5 to 49 CPU ticks/s on an unoptimised test build (React development mode inflates both).

Transcript blocks in the direct viewport are separated by a blank row; assistant text and tool blocks have a two-column outer gutter, with markdown width reduced accordingly. The same message layout applies to replay and streaming drafts.

When tool output is expanded with Ctrl+O, Escape collapses it without changing the composer draft. An active approval, task/model/budget/rewind panel, confirmation or composer menu owns Escape first; the task panel also closes on Escape. Ctrl+O still toggles expansion.

The direct model picker displays model IDs separately from a provider column and shows configured nicknames for each provider/model pair. Nickname filtering reads the attached session settings; selection still uses the actual provider/model ID, and the picker does not edit nicknames.

Local command output anchored to a live assistant draft follows the wire message that explicitly replaces that draft; a missing anchor falls back to the current transcript end, never its beginning. `/usage` during a live turn reports the usage accepted so far, not projected future usage.

The resume picker shows the selected session’s ID, update time, actual message count when available, model, and initial prompt in its responsive preview; the count is from the workspace-scoped session catalogue, not inferred from displayed text.

The throttled transcript frame records whether it was rendered for expanded output. Discard a frame when that mode changes: otherwise collapsing Ctrl+O can briefly repaint stale expanded output into normal flow. Failed settled tool rows are visually bounded in Static; the full underlying output remains in the on-demand viewer.

Pasted images arrive from ink-prompt as editor-only private-use markers plus image refs. Strip only image markers when sending or recording history, not while restoring a rejected draft; preserve image bytes separately. Paste-text blocks are not image markers. User transcript rows show the attachment count.

`/settings` opens a modal picker: Tab changes categories, typing searches all visible settings (including advanced entries), Enter starts an explicit value edit, and Escape cancels the edit or closes the picker. It receives redacted display values from the app and applies changes through the existing session settings command; secret values are redacted and secret/structured values are not directly edited in the picker. Closing while a change is pending does not cancel it and its eventual result is reported. Explicit `/settings <category>` and `/settings <key> [value]` remain available.

The slash menu uses the active skin’s MenuFrame titled `Commands`. Its visible item window fits short terminals while keeping the selected item reachable by Up/Down; at normal height it still shows up to ten entries.
