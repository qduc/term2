# Direct TUI integration

This subtree targets the staged direct protocol at `82d37ded91705090bc6b253301c7411ac5d5e389` and native command writer `f14c9baa`. The app owns connection, theme/skin providers, exit, host commands and session switching. Missing capabilities surface their real errors; the TUI does not call Session/Engine or create a fallback runtime.

The client folds `reduceWireEvent` into a fresh snapshot or a retained snapshot at the exact replay cursor. The app must retain state and cursor from the same consumption cut. Closing detaches without cancelling. Mixed transcript order is used only when supplied by `timeline`; unmatched tool results and other unordered items are identified separately. Images in tool results are placeholders.

A pending interaction belonging to the active root turn takes keyboard ownership automatically when no explicit task, budget or rewind overlay is open. `InteractionView.turnId` and `taskId` retain wire ownership rather than inferring it from display labels; task-owned requests do not take over the foreground composer. The ordinary composer keeps its draft but is inactive while the keyed interaction panel owns input. Ctrl+G returns from any interaction panel to the preserved composer without resolving or cancelling the request, so `/answer` and steering remain accessible. Only that exact root request is dismissed from automatic presentation; a new request takes ownership again. From the composer Ctrl+G opens the request-ID-scoped picker, including background requests and only explicitly advertised grants; Ctrl+B handles pending budget requests with explicit human extend or stop. The approval panel exposes `y`/1 for Allow once and `n`/2 for optional rejection-reason entry (empty Enter denies without a reason), with a separate explicit no-reason choice. Modified keys are not approval shortcuts. `Questions` owns structured question presentation; the pending-interaction summary does not echo all raw question arguments and expose non-current pages as active content. While pending, the `ask_user` tool header stays a neutral tool-name summary rather than repeating every page prompt. Completed tool output and its question/answer display remain visible; they are not an active question page. The question editor keeps partial answers local, supports `n`/`p` navigation, and places multi-select Continue directly after the offered options; it sends the complete typed answer set once rather than dispatching on navigation. Escape from an automatically selected approval cancels the foreground; from the first question it declines the question. Explicit picker/back navigation remains local. Decisions carry user provenance. `/tasks` displays supplied task data and sends selected task-ID-scoped operations; host task control can be unavailable, and acknowledgements do not imply completion. `/cancel` reports the actual targeted abort result and discarded IDs when available.

Enter steers during an active turn, Alt+Enter submits a follow-up, and idle Enter uses auto delivery. Queue operations use native commands; the queue editor retains original non-primary content, sends replacements only when changed, and never automatically resubmits a late edit. If content is unavailable it cannot recover unknown attachments. `/rewind` restores the Session draft and only resends on explicit request. History uses `envPaths('term2').data/tui-history-next.json` and stores image bytes; question answers are excluded. Concurrent history writers can race.

The app's `switchSession` attaches the successor and returns an optional notice after publication (including a control socket rebind failure). The unkeyed exported `Tui` retains that notice above its keyed session child. `/bridge` uses app-owned socket lifecycle callbacks.

Retry, compact, rewind and rollover use a fresh stable UUID per deliberate invocation and are sent once. Pending is not success; transport loss or interrupted outcome is reported as uncertain, without automatically repeating the effect. The retained ID can be queried with `/command-status <id>`; `/command-apply <id>` explicitly restores a completed rewind draft or follows a completed rollover successor. A pending rewind originally requested as resend is restored for review, not automatically resent. Snapshot command receipts remain visible. App-owned configure commands need the same keyed receipt semantics; they are not implemented by this subtree.

Integration verification must cover snapshot/replay, input ownership and terminal rendering (including automatic foreground versus explicit background decisions), attachments and late queue edits, task and budget decisions, switching/rebind notices, and actual application integration. Module presence or an accepted wire receipt alone is not proof that the keyboard workflow reaches the next provider/tool output.
