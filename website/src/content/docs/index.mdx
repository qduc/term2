term2 is an open-source AI assistant that can read your project, edit files, and
run commands in a local or SSH workspace. Choose your provider, review proposed
actions, and pick up a saved conversation after a break.

## Install, connect, explore

Use Node.js 20 or newer (Node 24 recommended).

```bash title="Install"
npm install --global @qduc/term2
term2 --version
```

On Linux, sandboxed shell commands also need `bubblewrap`, `socat`, and `ripgrep`.
See [installation](/term2/getting-started/installation/) for platform details.

Authenticate with [a supported provider](/term2/providers/), then run
`term2 --model` in your project. Select a model from that provider, enter `/plan`,
and ask where the project starts and how to test it.

[Follow the first-run guide →](/term2/getting-started/first-run/)

## Your models, your workspace

OpenAI, ChatGPT/Codex, Grok, and OpenRouter are built in. Add direct Anthropic,
Gemini, or local endpoints through `/providers`. Model capabilities and costs
depend on the provider and model you choose.

term2 is MIT licensed. Hosted providers receive the context and tool results
used for your request, and their billing and account limits apply.

[Provider setup](/term2/providers/) · [SSH workflows](/term2/remote/ssh/)

## Review the work as it happens

Start in Plan mode for read-only investigation. In Standard mode, shell commands
prompt by default; valid local workspace edits can apply without a prompt. The shell
sandbox constrains command execution; changing approval or sandbox settings
changes those boundaries.

For longer tasks, explore [subagents](/term2/modes/subagents/),
[saved sessions](/term2/using-term2/sessions/), and
[approval controls](/term2/safety/approvals/) when you need them.

## Know which version you're using

Check `term2 --version` for your installation and
`npm view @qduc/term2 version` for the latest published release. See
[what's new](/term2/getting-started/whats-new/) for release highlights.

This is the product documentation site. The separate `web-client/` app uses the
private [`term2 serve` gateway](/term2/remote/web-gateway/); it is a different
interface with its own setup.
